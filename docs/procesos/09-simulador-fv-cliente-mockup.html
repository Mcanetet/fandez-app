Simulador FV para el cliente

Mockup de producto · Fandez · TO-BE · cómo se vería en la app
Idea: el cliente ingresa su boleta, elige cuánto quiere ahorrar y “juega” con kits hasta ver precio del proyecto.

Simulación de ejemplo (RM, On-Grid Netbilling): boleta actual $120.000/mes → meta de ahorro 70% → kit sugerido 5 kWp · precio referencial proyecto $5.950.000 · nueva boleta ~$36.000 · retorno ~4–5 años. Precios “desde” de mercado Chile 2026 (llave en mano + SEC); el diseño final lo confirma la visita técnica.

2. Lógica detrás (para producto)

Regla simple que el cliente entiende; el socio/técnico afina en la visita.

boleta_mes = input cliente (CLP)
ahorro_% = slider 40–90%
ahorro_mes = boleta_mes × ahorro_%
boleta_nueva ≈ boleta_mes − ahorro_mes
kWp_sugerido ≈ round( (boleta_mes / 20.000) × (ahorro_% / 0.70) ) // ~$20k ahorro/mes por kW
precio_proyecto = catálogo kit[kWp] // admin/precios mercado RM
retorno_años ≈ precio_proyecto / (ahorro_mes × 12)

3. Momento en el journey FV

  1. Antes del pedido: simulador en vertical Fotovoltaica (sin compromiso) → CTA “Pedir evaluación”.
  2. Intake: se guarda boleta, % deseado y kit tentativo; el cliente paga la evaluación.
  3. Visita: técnico confirma techo/tablero; socio ajusta propuesta (puede subir/bajar kWp).
  4. Contrato: precio cerrado + abonos por hito (como en procedimiento 08).

4. Qué NO promete la UI

  • No garantiza el % exacto: clima, orientación, sombras y hábitos cambian el resultado.
  • No sustituye TE-4 / SEC / distribuidora: el socio instalador autorizado lo tramita.
  • No es cotización vinculante hasta evaluación + contrato firmado.
  • Batería e híbrido se muestran como “extra” aparte del On-Grid base.
